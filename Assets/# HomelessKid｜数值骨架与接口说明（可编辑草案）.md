# HomelessKid｜数值骨架与接口说明（可编辑草案）

目的：先把 **PlayerStatus（饱食/健康/心情/想象力/安全感）** 以及 **TimeService / ActionResolver / ShelterSystem** 的"输入→输出→可调参数→依赖"骨架搭好。你后续只需要改参数表与规则段落，就能快速迭代。

## 0\. 核心原则（先写死，避免跑偏）

- **失败条件只看 mood**：mood 归零 = 游戏失败（小熊离开/心里撑不住）。
- **hunger / health 归零不结束游戏**：触发"被救/回溯"惩罚机制（见 1.4），并将 **mood 直接减半**。
- **压力来自"数值消耗 + 机会成本"**：通过 hunger / health / mood 的持续消耗，迫使玩家每天投入约 **1/3-1/2** 的时间去找吃的、规避风险、回基地休息与整理；同时用晚回家、天气差、错过刷新窗口等机会成本放大压力。
- **UI 表达要直观**：hunger、health 用百分比条（同类生存游戏常见表达）；mood 用"小熊状态/心跳感"做情绪化表达，但底层仍是 0-100。

## 1) PlayerStatus（玩家状态数值）

### 1.1 数值清单（精简版｜以"生存 + 精神压力"为核心）

设计取向：不堆叠情绪相关数值；**mood 统一承载情绪/安全/心理稳定**。

| Key | 名称  | 范围  | 核心作用 | 上升来源 | 下降来源 | UI 表达 |
| --- | --- | --- | --- | --- | --- | --- |
| hunger | 饱食  | 0-100 | 生存压力 / 行动力核心 | 吃东西、睡觉小幅恢复、基地加成 | 时间流逝、翻找/劳动、夜晚未进食 | **百分比条** |
| health | 健康  | 0-100 | 风险承受 / 长线惩罚 | 睡觉、休息、干净食物 | 不新鲜食物、翻桶风险、雨淋、寒冷 | **百分比条** |
| mood | 精神  | 0-100 | 失败条件 / 情绪与安全总表征 | 捡到好玩的垃圾、善意任务、自己创意手工、环境舒适 | 夜晚在外、饥饿、被驱赶、失败事件 | **小熊状态（数值隐藏/可选显示）** |

### 1.2 派生状态机（由 3 个数值驱动）（由 3 个数值驱动）

- **虚弱（Weak）**：hunger ≤ H_WEAK
  - 行动/交互效率下降，明确提示需要进食。
- **生病（Sick）**：health ≤ HP_SICK
  - 行动消耗增加，翻找风险提高，强烈引导休息。
- **精神不稳（Unstable）**：mood ≤ M_LOW
  - 这个mood可能没必要设置这个，因为它的值已经直接了影响游戏的结束
  - 正向事件概率下降（垃圾概率下降或质量变差），部分互动表现更冷淡

mood 承担"安全感/童真滤镜"的功能：通过**事件与表现差异**体现，而不是新增数值。

### 1.3 数值变化统一入口（建议）

- 所有变化统一通过 ApplyDelta(source, deltas, tags)
- mood 的变化可被 isNight / inShelter / isRaining / wasChased 等 tag 修正
- 记录日志以支持调参

### 1.4 归零规则（关键：失败与惩罚）

你的设定在这里写死，后续调参只改"回溯天数/救援触发条件"。

- **mood = 0 → 游戏失败**
  - 叙事解释：住在心里的"小熊"离开/崩溃。
- **hunger = 0 或 health = 0 → 触发"救援/回溯"**（不算失败）
  - 共同惩罚：**mood 立刻变为原值的 50%（减半）**
  - 然后二选一（可由难度/设置决定）：
    - **时间回溯**：回到 **N 天前** 的存档状态（基地/背包/任务按规则回退）
    - **神秘魂灵救活**：直接把玩家送回基地/安全点，设定最低保底值（示例：hunger=20, health=20），并附加 1-2 天的"虚弱/病弱"Debuff

设计建议：

- 新手/叙事向：更偏"魂灵救活"
- 硬核/挑战向：更偏"时间回溯"
- 1让游戏沉浸感降低，人突然就返回几天前了，没道理。同时1还要一直保存7天内的每日存档信息，不知道技术实现难度如何和内存大小
- 2的话不知道难度会不会上升，毕竟降低50%mood的情况下游戏通关会很难（后续可能可以调数值解决）；同时这个魂灵的身份也是一个坑，不仅给游戏世界观带来的一些魔幻色彩，还可能会影响后续的剧情。PS:难道魂灵是死去的父母或者是之前的小哥哥

## 2) TimeService（时间与一天结构）（时间与一天结构）

### 2.1 一天结构（可调）

| 参数  | 含义  | 默认建议 |
| --- | --- | --- |
| DAY_LENGTH_MIN | 一天现实时间长度（分钟） | 15-25 |
| TICK_SEC | 数值更新 tick（秒） | 1.0 或 2.0 |
| MORNING_START | 早晨起点 | 06:00 |
| NOON_START | 中午  | 12:00 |
| EVENING_START | 傍晚  | 18:00 |
| NIGHT_START | 夜晚  | 21:00 |

**时段仅用于规则触发**：夜晚在外→除了特定区域，其余地方捡不到垃圾；傍晚→提示回家；清晨→刷新点重置。

### 2.2 TimeService 输出（供别的系统订阅）

- OnTick(deltaSeconds)
- OnTimeSegmentChanged(segment)（Morning/Noon/Evening/Night）
- OnDayEnded() / OnNewDayStarted(dayIndex)

### 2.3 时间推进方式（两种并存）

- **连续推进**：随现实时间流逝（探索时）。
- **跳时推进**：睡觉/打盹/剧情（一次性推进到某个时间点）。

统一用 AdvanceTime(minutes, reason) 进入，方便统计与事件系统监听。

## 3) ShelterSystem（秘密基地/模块加成）

### 3.1 基地阶段 Stage（强烈建议做成数据表）

| Stage | 名称  | 解锁条件（例） | 关键加成（例） |
| --- | --- | --- | --- |
| 0   | 无家/露宿 | 初始  | 睡眠收益低；夜晚安全感掉更快 |
| 1   | 废棚子角落 | 木板x? 布x? | 睡觉恢复 +；mood基础值 + |
| 2   | 能遮雨的小窝 | 增加屋顶/门帘 | 雨天惩罚减弱；睡觉恢复再提升 |
| 3   | 稍像"家"的基地 | 墙面/储物 | 更稳定的 Buff |

**规则建议**：基地阶段影响的是"倍率/上限"，不是直接给资源。

在房屋内不能影响mood，但是房屋stage上升是可以一次性增值mood的

（不知道技术实现难度怎样，但我真的很想让玩家可以DIY房屋，就是在基础stage满级后，可以装饰自己的小屋，把自己用垃圾做的小玩具或摆件浪漫地布置在家中，每个布置都会给mood带来增长）

### 3.2 模块 Modules（可堆叠的小加成｜统一作用于 mood）

- **休息区（Bed/Mat）**：睡觉时 health / mood 回复倍率 +
- **遮雨（Roof）**：雨天在基地时 mood 掉速 -（基于下雨天会掉mood的背景）
- **光源（Candle/Light）**：夜晚 mood 更稳定，低 mood 更难触发
- **舒适物（Decoration/Toy）**：被动 mood 小幅恢复
- **收纳（Box/Shelf）**：整理耗时 -（体验向）

### 3.3 ShelterSystem 接口（给 ActionResolver 调用）

- GetRestRecoveryMultiplier()（影响 health/mood 恢复）
- GetMoodStabilityModifier()（夜晚/雨天 mood 掉速修正）
- GetWeatherProtection()（雨淋/寒冷对 health 的修正）

## 4) ActionResolver（行为结算器：把"动作"变成"数值变化"）

### 4.1 动作分类（最小集｜已合并情绪类数值）

| Action | 输入  | 输出  | 常见依赖 |
| --- | --- | --- | --- |
| Eat(foodId) | 食物数据 | hunger↑ health± mood± | 食物新鲜度 |
| Sleep(duration) | 时长 / 是否在基地 | 时间推进 + health↑ mood↑ | ShelterSystem |
| TrashSearch(pointId) | 点位数据 | 物品 + health 概率↓ + mood↓ | 夜晚 / 天气 |
| TaskTurnIn(taskId) | 任务对象 | mood↑ | 任务类型 |
| RestAtShelter() | 基地状态 | mood↑（安心/安全的统一表达） | ShelterSystem |

### 4.2 统一结算流程（建议模板）

- **校验**：是否能做（冷却/是否夜晚/是否在范围）
- **成本**：推进时间、消耗物品
- **结果**：掉落/奖励
- **数值变化**：调用 PlayerStatus.ApplyDelta(...)
- **触发事件**：给叙事/音效/提示（非数值）

## 5) 可调参数表（你后续主要改这里）

建议把这段单独做成 ScriptableObject/JSON，但现在先在文档里占位。

### 5.1 阈值（状态机门槛｜精简后）

| 参数  | 默认  | 说明  |
| --- | --- | --- |
| H_WEAK | 25  | 饱食过低进入虚弱 |
| HP_SICK | 30  | 健康过低进入生病 |
| M_LOW | 30  | 精神不稳阈值 |

### 5.2 Tick 掉速/回速（基础值｜精简后）

| 参数  | 默认建议 | 说明  |
| --- | --- | --- |
| HUNGER_DECAY_PER_HOUR | 6   | 每小时饱食下降 |
| MOOD_DECAY_WHEN_HUNGRY | 1   | 饥饿时每小时精神额外下降 |
| MOOD_DECAY_AT_NIGHT_OUTSIDE | 8   | 夜晚在外每小时精神下降 |
| HEALTH_DECAY_WHEN_SICK (可选) | 0   | 生病状态下的额外健康衰减（不用可留 0） |

### 5.3 行为结算（示例占位）（示例占位）

- Eat：
  - hunger += food.hungerValue
  - if food.freshness < F_BAD: health -= RISK and mood -= SMALL
- TrashSearch：
  - time += SEARCH_MINUTES
  - chance = baseRisk \* (isRaining?1.2:1) \* (isNight?1.2:1)
  - if rand < chance: health -= RISK
- Sleep：
  - time += duration
  - hunger += SMALL (可选)
  - health += BASE \* ShelterMultiplier
  - mood += BASE \* (inShelter?1:0.5)

## 5.4 生存时间占比标定（默认方案｜目标：每天 1/3-1/2 时间用于生存）

本段**直接给一套可用默认值**，用于验证"生存压力是否成立"。假设：

- **一天现实时间 = 20 分钟**
- 目标：**6-10 分钟/天** 必须用于吃饭、找食物、翻找、回基地休息、整理

### A) 时间与需求节奏设计

- 每 **4-6 分钟** 必须处理一次「生存问题」之一：
  - 吃点东西（饱食）
  - 回基地睡/休息（健康 + 安全感）
  - 为今晚做准备（食物/遮雨/光源）

如果玩家**连续 6 分钟只探索不管生存**，至少会触发一个负面状态（虚弱 / 恐惧 / 生病倾向）。

### B) 建议基础掉速（按 20 分钟/天反推）

| 数值  | 调整后建议 | 设计意图 |
| --- | --- | --- |
| HUNGER_DECAY_PER_HOUR | **18** | 约 6-7 分钟进入「明显饥饿」，逼迫进食 |
| MOOD_DECAY_WHEN_HUNGRY | **2** | 不吃会影响情绪，但不是立刻崩 |
| MOOD_DECAY_AT_NIGHT_OUTSIDE | **20** | 夜晚 2-3 分钟就明显危险，强推回家 |

解释：

- 现实 20 分钟 ≈ 游戏 24 小时
- 18/小时 ≈ **每 3.3 小时掉 1 点饱食** → 约 6-7 分钟掉到虚弱线

### C) 典型一天的"时间被吃掉"示例

- 早上：
  - 找吃的 / 吃（1-2 分钟）
- 中午前后：
  - 翻找 1-2 个点位（2-3 分钟）
- 傍晚：
  - 整理 / 回基地 / 准备睡觉（1-2 分钟）
- 夜晚：
  - 睡觉 / 被迫休息（2-3 分钟）

👉 合计：**6-10 分钟 = 30%-50% 时间** 被生存系统"吃掉"。

### D) 为什么玩家不会觉得烦（而不是紧张）

- 生存行为**本身有掉落/叙事/世界反馈**（不是纯扣数值）
- 基地升级会**明显缩短生存所需时间**（压力曲线下降）
- 中后期：
  - 生存 ≈ 20-30%
  - 探索/任务/情绪体验 ≈ 70-80%

如果测试时发现：

- 玩家无视生存 → 掉速不够
- 玩家只顾生存 → 掉速过猛 or 掉落不足

## 7) 下一步你最值得先定的 5 个决定（不定就难调参）

- **一天现实长度**（15/20/25 分钟？）
- **hunger 掉速是否与行动相关**（只随时间？还是跑动/翻找额外消耗？）
- **hunger/health 归零的惩罚模式**（回溯 N 天 vs 魂灵救活；以及 N 的默认值）
- **mood 的主要压力来源权重**（夜晚在外 / 被驱赶 / 饥饿联动，各占多少）
- **基地升级能把生存占比压到多少**（从 30-50% → 20-30% 的目标阶段）
