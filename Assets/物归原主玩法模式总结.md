# 物归原主玩法模式总结（现实推理向）

> 目标：将“失物归还”从单一跑腿，扩展为可复用的微型解密任务体系。  
> 设计方向：跨 2-3 个区域跑链，强调现实推理、环境证据与人物故事回响。

---

## 1. 核心设计原则

1. **失物即线索入口**：玩家捡到物品后，不直接得到答案，而是得到可行动信息。  
2. **多通道推进**：问路人是可选路径，不是唯一解法；环境互动同样可解题。  
3. **现实推理优先**：线索来自可验证信息（刻字、地址、票据、制服、工坊标记、课程信息）。  
4. **跨区跑链但不拉扯**：每个任务主链控制在 2-3 区域，避免无意义折返。  
5. **每个任务有故事回响**：归还后给世界反馈（对话变化、小道具变化、后续任务钩子）。

---

## 2. 玩法结构（通用状态流）

**发现失物 → 获取线索 → 处理/验证 → 锁定失主 → 归还/放置 → 回响**

建议任务状态机：

- `未发现`
- `已拾取`
- `已获得初线索`
- `处理中（搜集/拼装/清洁/查询）`
- `已识别失主`
- `已归还（完成）`

---

## 3. 可复用玩法模块库（12个）

每个任务选 3-6 个模块串联即可，不必全部使用。

### M01 观察取证（Inspect）
- 拾取后可查看细节，获得第一条可推进线索。
- 线索载体：刻字、落款、地址、班级、工坊印章、钥匙编号。

### M02 局部搜集（Nearby Gather）
- 在附近 2-4 个交互点找配件/残片。
- 常见对象：布娃娃缺件、撕碎纸条、钥匙扣另一半。

### M03 组合修复（Assemble/Repair）
- 在特定工作台或地点拼装/修复，解锁新信息。
- 典型地点：慢工小巷工作台、作坊桌台、教堂桌面。

### M04 清洁显形（Clean/Reveal）
- 通过清洗、晾干、擦拭让隐藏信息可读。
- 典型信息：褪色文字、底纹标记、隐约编号。

### M05 位置对位（Place/Slot）
- 先把物品放回正确场景点，再触发下一线索。
- 典型点位：捐献箱、墓前、门口挂钩、失物台。

### M06 票据追踪（Paper Trail）
- 通过记录类证据锁定区域或人。
- 证据来源：订单、收据、课堂通知、登记簿。

### M07 职业匹配（Occupation Match）
- 通过材质/污渍/使用痕迹推断职业圈层。
- 示例：果酱渍=作坊、木屑油渍=木工、粉末=烘焙。

### M08 候选排除（Candidate Elimination）
- 给 2-3 个合理候选，用证据逐一排除到唯一。
- 必须保证“排除后有正反馈”，避免纯试错。

### M09 时间窗验证（Time Window）
- 某 NPC 或某线索仅在特定时段有效。
- 作用：强化真实感，拆分“白天搜证/傍晚交付”节奏。

### M10 环境补证（Environmental Proof）
- 在目标区域找到与失物一致的环境证据，完成闭环验证。
- 示例：同款补丁、同工坊印章、同批次标记。

### M11 可选询问网络（Optional Ask）
- 询问路人提供方向线索，但不直接给答案。
- 信息分层：区域方向 → 候选名单 → 验证建议。

### M12 归还回响（Deliver & Aftermath）
- 归还后发放奖励并更新世界状态。
- 回响类型：NPC态度变化、公告更新、新支线解锁。

---如果不复用这个模块库，也就是更自由的话：
例子有，捡到一个怀表，可以直接通过辨识上面的名字或照片来归还。但是如果让整个过程更具有挑战性，就可以让获得怀表更困难，比如玩家发现怀表卡在了

## 4. 跨区域跑链模板（2-3区）

### 模板A：来源追踪链
`区域A发现失物（M01） → 区域B查来源记录（M06/M07） → 区域C交付（M12）`

适合：钥匙、工具、工作牌、订单类物品。

### 模板B：修复识别链
`区域A拾取残缺件（M02） → 区域B修复/显形（M03/M04） → 区域C排除候选并归还（M08/M12）`

适合：布娃娃、破照片、撕碎信件。

### 模板C：地点归还反推链
`区域A推断应放地点（M05） → 区域B触发补证（M10/M06） → 区域C人物确认与完成（M12）`

适合：十字架、纪念物、宗教或家族物件。

## 6. 已讨论的4个任务原型（可直接扩展）

### 6.1 情书归还（问询 + 区域验证）
- 目标体验：社交调查 + 现实线索比对。
- 推荐模块：`M01 → M11 → M08 → M10 → M12`
- 推荐链路：桥钟广场 → 红果作坊街/旧石街区（二选一排除）→ 失主所在点
- 验证线索示例：落款、职业习惯、常出现时段。

### 6.2 钥匙归还（编号/用途追踪）
- 目标体验：从“钥匙是开哪里”反推“属于谁”。
- 推荐模块：`M01 → M06 → M07 → M12`
- 推荐链路：旧石街区 → 慢工小巷 → 对应住户/工坊主
- 验证线索示例：钥匙编号、锁型、钥匙扣材质磨损。

### 6.3 作业本归还（身份与地点匹配）
- 目标体验：轻推理 + 时间窗。
- 推荐模块：`M01 → M06 → M09 → M12`
- 推荐链路：教堂公墓周边拾取 → 学校/公告信息点 → 放学时段交付
- 验证线索示例：班级、课表、老师批注风格。

### 6.4 十字架归还（地点归还 + 人物确认）
- 目标体验：先放置再确认，带情绪回响。
- 推荐模块：`M01 → M05 → M10 → M12`
- 推荐链路：教堂公墓发现 → 教堂放置点 → 守墓人/神职角色确认
- 验证线索示例：铭文年份、家族姓氏、墓区对应关系。

## 7. 布娃娃任务样例（环境互动型）

任务物：布娃娃躯干

推荐流程：

1. `M01`：拾取躯干，看到“缝线断裂，缺少部件”。  
2. `M02`：在附近找 2-3 个零件（手臂、纽扣眼、标签片）。  
3. `M03`：到慢工小巷工作台拼装。  
4. `M04`：在作坊街清洁后显出刺绣缩写或店铺标。  
5. `M08`：在两个候选家庭/NPC中做排除。  
6. `M12`：归还并触发故事回响。  

推荐链路：桥下滩地（发现）→ 慢工小巷（修复）→ 红果作坊街或旧石街区（确认与归还）

## 8. 防卡规则（现实推理向）

1. **主线索永不缺失**：至少 1 条线索一定可拿到。  
2. **每步至少一个正反馈**：找到部件、触发新描述、缩小候选都算进展。  
3. **失败不硬惩罚**：问错人不扣太多资源，优先给反向提示。  
4. **三层提示机制**：主角独白微提示 → 环境高亮提示 → 路人兜底方向。  
5. **避免纯时间门**：时间窗用于验证，不用于强制等待。  

---

## 9. 任务分布建议（与你的标定方式兼容）

你已确定“难度由你手动标定”，可采用以下投放策略：

- 前期：简单/中等为主，穿插少量复杂任务做记忆点。  
- 中期：中等为主，复杂比例提升。  
- 后期：复杂为主，但保留少量简单任务调节节奏。  
- 任意阶段都允许混合难度，确保世界“真实而非关卡化”。

## 10. 落地建议（和当前项目系统对接）

可复用现有系统：

- `DayManager`：用于任务出现日/时段触发。  
- `InteractableBase` + `InteractionManager`：用于路人问询、工作台、放置点交互。  
- `ItemData`：扩展任务字段（失主、线索、步骤状态、候选列表）。  
- `TrashSpawner`：任务物品可走专门生成逻辑，与普通拾荒分开控制。

## 11. 下一步执行清单（建议）

1. 先定 6-8 条首批任务，覆盖 4 类模板（问询、修复、票据、地点归还）。  
2. 每条任务写“1显性线索 + 1验证线索 + 1兜底线索”。  
3. 每条任务绑定 2-3 个区域，并画出地图跑链。  
4. 在场景里先放“交互点占位物”做灰盒验证（不急着做美术）。  
5. 跑一轮 30 分钟测试，检查卡关率与平均耗时。
